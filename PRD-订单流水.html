1.1 背景

旧原型将「门店流水 / 退款」简化为导航占位页（开单结账 PRD 中曾称 s8 / s9）。现将 BillingDemo 订单流水整组迁入 flow/，替换占位，作为开单成功后的主售后链路。

1.3 本期做（In）

  • 门店流水列表（Tab：全部 / 项目 / 产品 / 会员卡 / 团购券 / 作废 / 退款）+ 筛选 sheet
  • 订单详情（消费内容、优惠、业绩提成只读展示、修改订单入口、退款/作废、差额条）
  • 修改订单（增删改项目/产品/办卡/充卡三型、员工与提成、保存与差额两选）

模块 4　状态机

4.1 订单状态 status

值文案列表 Tab可改单可退款可作废
done已完成（详情常不打 pill）全部/项目/产品/会员卡/团购券✓✓✓
partial_refund部分退款退款（及全部不展示为活跃）✗✓（剩余）✓
refund已退款退款✗✗✗
void已作废作废✗✗✗

活跃单过滤：flowIsActiveOrder = 非 void / refund / partial_refund。

「全部 / 项目 / 产品 / 会员卡 / 团购券」Tab 只展示活跃单（团购券 = kind: group|tuangou）；「作废」「退款」Tab 按状态。

4.2 门控函数（原型）

  • flowCanEditOrder(o) → status === 'done'
  • flowCanRefundOrVoid(o) → done \| partial_refund

4.3 退款笔 refundKind

  • 该笔退后原单无剩余可退 → 全退口径（订单变 refund）
  • 仍有剩余 → 部分退（订单 partial_refund）；记录笔可标「全退/部分退」语义（以原型展示为准）

4.4 改单草稿

进入修改订单时拷贝 flowEditDraft；保存时校验 → 无差额直接落库；有差额先弹 flowEditDiffMask，确认后再 applyFlowEditDraft 并闭合支付。

- 时间筛选：月历（‹ 2026年9月 › 翻月，可一直往前翻到任意历史月份、不可翻到未来月；最新月为当前月）；每个日期格显示「日号 + 该日实付总额」（无流水的日子不显示金额，有单但实付为 0 的日子显示 ¥0）；当天描圈、选中日品牌色实心、未来日置灰；点某日＝选中该日（不改列表），需再点「确定」生效；「全部时间」清除日期条件

- 条件筛选（四组，点选即改草稿，仍需「确定」生效）

- 价格区间（比实付，与日历日额同一口径）：全部 / ¥0–100 / ¥100–300 / ¥300–500 / ¥500以上 / 自定义（最低价–最高价，档位区间为左闭右开，自定义为双闭区间）；自定义留空 → 不限制该端，两端都空 → 提示「请填写价格区间」；最低价 > 最高价 → 提示「最低价不能高于最高价」

- 支付方式：全部 + 流水里真实出现过的渠道（种子下为 现金 / 微信 / 支付宝 / 会员卡 / 美团 / 抖音）

- 散客 / 会员：全部 / 散客 / 会员

- 服务员工：全部 + 流水里真实出现过的服务人（多选，点「全部」清空）

- 页脚：重置 / 确定（sheet 内页脚，非悬浮 bar）

  • 实付口径（日历日额）：逐支付行判定 —— 团购券单（kind: group）整单计 0；渠道为经理签单或会员卡（卡付）的行不计；混合支付按行累加（如 支付宝 80 + 现金 40 记 120）；作废 0；已退款 0；部分退款记为「实付 − 已退」。日历只统计日期，不按 Tab 过滤。
  • Tab：全部 | 项目 | 产品 | 会员卡 | 团购券 | 作废 | 退款（一行均分，不换行、不横滑）
  • 流水卡：头像 + 姓名 | 状态 | › ；类型标签 + 首项名（多项「等 N 项」）+ 服务人 | 标价；支付行（渠道图标 + 方式 | -¥）;实付总额；开单时间。部分退额外「已退 ¥」。右下「实付总额」取统一实付口径（与日历日额、价格区间筛选同源）：团购券单 / 作废 / 已退款 = ¥0，部分退 = 实付 − 已退，卡付·经理签单行不计，混合支付按行累加
  • 团购券单：名称位显示券名，金额位显示券面核销金额（即订单金额，不进「等 N 项」）；右下「实付总额」为 ¥0（券款不进实付，与日历一致）
  • 空态：暂无流水 / 暂无作废订单 / 暂无退款订单（副文案见原型）

  1. 备注选填（max 200）；合计退款；确认后写 refunds[]（refundKind: full|partial）、更新状态，列表切「退款」Tab

模块 8　业务规则

  1. 仅已完成可改单；部分退/全退/作废不可改单。
  2. 改单至少 1 个项目；有员工且全店按工位时须设工位。
  3. 改单差额必须当场闭合。
  4. 部分退后可继续退剩余并可作废。
  5. 指定退：0 元实付分摊项不可指定金额。
  6. 充卡三种均须本次实付 > 0；续费不可用于已永久卡。
  7. 流水单号全列表唯一（原型范围；线上为全门店唯一）。
  8. 详情业绩/提成只读；提成在编辑项改。
  9. 支付渠道展示与补差支付枚举对齐开单结账；筛选的支付方式 / 服务员工 chips 由当前流水数据推导，非硬编码白名单。
  10. 实付口径（日历日额）：团购券单整单 0；经理签单、会员卡（卡付）支付行不计；作废 / 已退款 0；部分退款记「实付 − 已退」；办卡 / 充卡单照常计入。列表卡与详情页脚仍标「实付总额」＝该单核销/收款金额（团购券单会显示核销价，与日历不计入的差异待与设计确认是否改文案）。
  11. 权限 / 审计 / 真实退款到账 以线上为准。

模块 10　验收 P0 + 造数场景

10.1 造数

原型内置 FLOW_ORDERS：含散客/会员、项目/产品/办卡/直接收款、组合支付、部分退种子等。宿主 s6/s7 开单成功 unshift 新单（侧栏直达 s15 演示不写流水）。

10.2 Given → When → Then（P0）

  1. Given 宿主购物车有项并确认支付，When 进入 s15，Then 流水列表置顶可见本笔，且「看流水」进该笔详情。
  2. Given 进入订单流水，When 打开模块，Then 默认门店流水列表（非 Hub）。
  3. Given 列表，When 切 Tab「退款」，Then 仅 refund/partial_refund。

2a. Given 有团购核销种子，When 切 Tab「团购券」，Then 仅 kind: group 活跃单，且 Tab 行不横滑、不换行。

2b. Given 团购券列表卡，When 查看，Then 名称位为券名、金额位为核销实付；When 进详情，Then 消费内容为具体项目/产品且有「团购券」信息行。

2c. Given 未落项团购单，When 看详情，Then 明细为「直接收款（直）」并有灰字「团购券未指定消费项目，按直接收款计」。

2c-1. Given 团购券单详情，When 查看，Then 顶部无差额卡、金额区为「核销实付」且等于订单金额；「更多」无补收/退还差价。

2d. Given 任意订单卡或详情支付区，When 查看，Then 支付方式左侧有 14×14 渠道图标。

  1. Given 已完成单，When 点卡，Then 进详情且可「修改」。
  2. Given 已退款单，When 看详情，Then 无修改订单入口。
  3. Given 可改单，When 点开单时间笔并保存合法值，Then toast「开单时间已更新」且 meta 更新。
  4. Given 可改单，When 改单号为已占用号，Then toast「该单号已被使用」。
  5. Given 修改订单仅 1 项，When 删该项，Then toast「请至少保留一个服务项目」。
  6. Given 编辑项，When 点价格或笔，Then 打开金额键盘。
  7. Given 编辑项员工，When 看业绩，Then 只读；提成有笔可改。
  8. Given 添加项→会员卡→充卡→充值，When 看表单，Then 储值/赠送/实付均有方框笔。
  9. Given 续费且卡已永久，When 选该卡，Then 提示无需续费/不可续。
  10. Given 改价导致少收，When 保存，Then 差额对话框两按钮，无「仅保存」。
  11. Given 差额对话框，When 选其他支付方式，Then 打开确认支付 sheet 且可滚到现金等渠道。
  12. Given 可退单，When 不选题点确认，Then toast「请选择退款项」。
  13. Given 指定退回，When 看可改金额，Then 输入框旁有方框笔。
  14. Given 退部分项，When 确认成功，Then 状态部分退款且可继续退。
  15. Given 退完全部剩余，When 成功，Then 状态已退款，不可改单。
  16. Given 可作废，When 确认作废，Then 进作废 Tab 可见该单。
  17. Given 门店流水，When 点标题栏「筛选」，Then 打开 flowFilterMask：无 ×、无底部灰条、底部为「重置 / 确定」且两钮同高同基线；点 sheet 外空白即收起。

19a. Given 筛选 sheet「时间筛选」，When 查看日历，Then 每格显示「日号 + 该日实付总额」，当天描圈；When 点 ‹，Then 可一直往前翻到任意历史月份且不显示未来月数据；When 翻回当前月，Then › 置灰；When 点某日，Then 该日品牌色选中且列表不变；When 再点「确定」，Then 列表只剩该日订单，且标题栏「筛选」转为品牌色。

  4. Given 作废含卡消费单，When 确定作废，Then toast 含「会员卡额度已恢复」（有 mutations 时）。
  5. Given 详情有未闭合差额，When 点更多→补收/退差，Then 走差额支付或拦截 toast（无差额/方向错误）。
  6. Given ?flow=flow-edit，When 深链打开，Then 进入修改订单（无单时回落列表）。

10.2.1 R48 壳层：宿主导航与流水层的进出（26–31）

  1. Given 从侧栏「订单流水」任一入口进入流水层，When 点侧栏「主链路」的任意入口（如「首页」「选择顾客」），Then 退出流水层并显示该宿主页（#flowModuleRoot 无 is-active、#frame 无 is-flow-mode）。
  2. Given 同上，When 点侧栏「直接收款」的「直接收款 / 收款 / 开单结算」，Then 同样退出流水层并落到 s2 / s3 / s7。
  3. Given 上一步停留在某宿主页，When 再点侧栏「订单流水」任一入口，Then 流水层可再次打开，且该流水屏可见（不是全屏都 hidden）。
  4. Given 在流水层内点「门店流水」标题栏返回（或客户选择返回 / 挂单列表返回），Then 退出流水层并回到进入流水前的宿主页（navStack 顶；深链进入时为首页 s0）。
  5. Given index.html?flow=flow-list 深链打开，When 加载完成，Then 直接停在门店流水屏（宿主启动的「重置回首页」不得把它顶掉）。
  6. Given 全流程操作，When 观察控制台，Then 无 JS 报错。

（扩展用例可按 §6 逐条补；冲突以原型为准。）
