·1. 背景 / 目标 / 范围

1.1 背景

顾客在配套 C 端小程序扫码登录后进行自助买单，会预填一部分字段，生成一张需要商户侧补全归档的半成品订单，本文称为 「自助订单」。

自助订单出现在商户端首页特定区域（横向卡片流），也可在列表页集中处理。店员进入补全订单页补齐信息并归档后，半成品变为正式订单，进入现有 「订单流水」。

1.2 目标

  1. 让店员在商户端快速发现、筛选、补全并归档自助订单。
  2. 补全时支持消费内容、服务员工（点客/散客）、业绩提成、散客性别等。
  3. 归档结果进入订单流水，后续改单/退款走现有流水能力。

1.3 范围（In）

端能力
商户端首页待归档横滑卡流（按下单时间取前 5；尽头右滑进列表）
自助订单列表默认日期「全部」；搜索 / 筛选；按下单时间排序（无排列规则问号）
补全订单全屏补全 → 完成归档
桥接归档写入订单流水（开单人语义可为「自助买单」，另记归档人）
流水侧入口线上「订单流水」→「流水订单」页 →「自助收银」进入 s16（「门店流水 / 自助收银」形态沿用线上）

1.4 非范围（Out）— 硬边界

本次开发不改变线上现有以下能力的功能逻辑，仅作功能补充：

  • 开单结账（散客/会员开单、结算、成功页等）
  • 价目表
  • 业绩设置
  • 提成设置
  • 订单流水（列表/详情/改单/退款等既有逻辑）

本原型夹内首页「开单 / 开卡 / 挂单」仅为视觉占位，点击 toast「本原型仅演示自助归档」。完整开单链路见冻结目录 开单结账-主链路完整版/。

1.5 C 端半成品说明

  • C 端会预填一部分字段并完成支付（商户端实付金额与支付方式只读）。
  • C 端字段明细另附；本文只规定商户端可见 / 可改 / 只读字段（见 §6）。
  • 半成品在归档前不是正式门店订单；归档后才进流水。

·3. 端到端流程

C 端小程序自助买单（已付，预填部分字段）
        ↓
生成「自助订单」（待归档）
        ↓
商户端首页横滑卡流（最多 5 张）──尽头再右滑──► 自助订单列表页（s16）
        │                                      ▲
        └──────── 点击任意卡片 ─────────────────┤
                                               │
订单流水 → 流水订单页 →「自助收银」──────────────┘
（流水订单页另有「门店流水」；双入口形态沿用线上）
                        ↓
                 补全订单页（push）
           补内容 / 选员工 / 调业绩 / 备注…
                        ↓
                   完成归档
                        ↓
              正式订单 → 订单流水

导航栈（原型）：go(id) push；返回 goBack() pop。首页 → 列表 → 补全；或首页卡直接 → 补全；或 订单流水 → 流水订单 →「自助收银」→ 列表。s16 返回依来源：首页路径回首页；「自助收银」路径回流水订单页。归档成功 toast「已归档」后返回上一页并刷新卡流/列表。

5.3.12 智能补全规则与开关

何时跑：进入补全页且开关 开；或用户把开关从关拨到开。跑完 toast「已智能补全，请核对」。

补项目（仅明细模式且当前无明细时补 1 个）：

  1. 硬规则：候选售价必须 ≥ 订单实付 paid；否则剔除。
  2. 打分：价格贴近×0.5 + 上次消费项命中×0.3 + 近30天热销名次×0.2 + 项目类型小加成。
  3. 取最高 1 个写入；无合格候选则不补项目。

补员工：

  • 平均：确保全员条存在；若无人 active，按「项目常用员工」偏好激活一人。
  • 工位：若目标项尚无任何人，向大工位推入 1 人（偏好表，否则默认林屿森）；点客默认关。
  • 快捷模式：目标为订单级 orderStaff，基准金额=实付。

来源标记：由本规则自动写入的明细带 smart: true；卡片名称右侧追加小标签「智能补全」（§5.3.15）。手动添加、手动改过的明细无此标记。

·7. 业务规则（汇总）

  1. 半成品 ≠ 正式订单；归档后才进流水。
  2. 不改动开单结账 / 价目表 / 业绩设置 / 提成设置 / 订单流水既有逻辑。
  3. 实付与支付渠道商户端不可改。
  4. 内容侧：至少「有明细」或「快捷开单」才能归档。
  5. 员工可选；无员工可归档（toast 弱提示）。
  6. 点客 = 顾客指定；未开点客 = 非指定。
  7. 提成演示比例 10%（真实以门店提成设置为准，本功能不改设置模块）。
  8. 首页/列表按下单时间排序；首页最多 5 张；尽头右滑进列表；列表默认可看全部日期 pending。
  9. 选人 sheet 不展示本上下文已占用员工；无可选时 toast、不打开。
  10. 智能补全受顶栏开关控制；自动填入项售价不得低于订单实付。
  11. 消费内容默认平均分配；工位模式为演示切换。

·8. 验收要点（P0）

  1. C 端语义：半成品；归档后进流水。
  2. 首页卡流前 5；尽头右滑二楼进列表；列表左缘右滑回首页；点卡进 s17。
  3. 列表无 Tab；日期默认「全部」；筛选支付三档；筛选图标无灰圆底。
  4. 另入口：订单流水 → 流水订单 →「自助收银」进 s16；此路径返回回流水订单页（不回首页）；「门店流水 / 自助收银」形态沿用线上。
  5. s17 六段卡；顶栏智能补全 Switch 默认开；关则不自动填；售价≥实付。
  6. 默认平均分配全员条；工位模式三档 +「+」选人；点客绿标 85% 不透明；× 取消选择有效。
  7. 未选中条只显示「姓名 + 空灰条」；点客钮 / % / 业绩框 / × 仅选中后出现。
  8. 智能补全写入的明细，名称右侧显示「智能补全」小标签；手动添加项无标签。
  9. 快捷开单：红闪电标题 +「改为项目/产品」；价目无「猜你想加」。
  10. 选人 sheet：左点客、右 Switch、无 ×/无底提示、底栏 48；会员 sheet 白底。
  11. 业绩 sheet 空态完整；键盘可改业绩/提成。
  12. 票卡时间/件数/去尾零/会橙散蓝/二楼圆点规格仍成立。
  13. 归档成功 toast；pending 从卡流/列表消失；流水可桥接。
  14. 外网字体不阻塞首屏；流水大包可按需加载。
