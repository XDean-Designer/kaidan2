·1. 背景 / 目标 / 范围

1.1 背景

顾客在配套 C 端小程序扫码登录后进行自助买单，会预填一部分字段，生成一张需要商户侧补全归档的半成品订单，本文称为 「自助订单」。

自助订单出现在商户端首页特定区域（横向卡片流），也可在列表页集中处理。店员进入补全订单页补齐信息并归档后，半成品变为正式订单，进入现有 「订单流水」。

1.2 目标

  1. 让店员在商户端快速发现、筛选、补全并归档自助订单。
  2. 补全时支持消费内容、服务员工（点客/散客）、业绩提成、散客性别等。
  3. 归档结果进入订单流水，后续改单/退款走现有流水能力。

1.3 范围（In）

端 能力
商户端首页 待归档横滑卡流（按下单时间取前 5；尽头右滑进列表）
自助订单列表 默认日期「全部」；搜索 / 筛选；按下单时间排序（无排列规则问号）
补全订单 全屏补全 → 完成归档
桥接 归档写入订单流水（开单人语义可为「自助买单」，另记归档人）

1.4 非范围（Out）— 硬边界

本次开发不改变线上现有以下能力的功能逻辑，仅作功能补充：

  • 开单结账（散客/会员开单、结算、成功页等）
  • 价目表
  • 业绩设置
  • 提成设置
  • 订单流水（列表/详情/改单/退款等既有逻辑）

本原型夹内首页「开单 / 开卡 / 挂单」仅为视觉占位，点击 toast「本原型仅演示自助归档」。完整开单链路见冻结目录 开单结账-主链路完整版/。

1.5 C 端半成品说明

  • C 端会预填一部分字段并完成支付（商户端实付金额与支付方式只读）。
  • C 端字段明细另附；本文只规定商户端可见 / 可改 / 只读字段（见 §6）。
  • 半成品在归档前不是正式门店订单；归档后才进流水。

·2. 术语

术语 定义
自助订单 C 端自助买单生成的待归档半成品单
补全订单 商户端编辑并归档自助订单的全屏页（原型 s17）
归档 补全完成并提交，半成品变为正式订单并进入订单流水
点客 顾客指定的服务员工（与「散客」相对；选人 sheet 上的「散客」按钮 = 非顾客指定）
散客（顾客身份） 非会员顾客；展示名默认「散客」，可选性别变为「男散客」「女散客」
快捷开单 补全页不写项目/产品明细、以订单级员工服务整单的内容模式（价目 sheet 入口）
会 / 散标 票卡左下角类型标：会员橙「会」、散客蓝「散」

·3. 端到端流程

C 端小程序自助买单（已付，预填部分字段）
        ↓
生成「自助订单」（待归档）
        ↓
商户端首页横滑卡流（最多 5 张）──尽头再右滑──► 自助订单列表页
        │                                      │
        └──────── 点击任意卡片 ─────────────────┘
                        ↓
                 补全订单页（push）
           补内容 / 选员工 / 调业绩 / 备注…
                        ↓
                   完成归档
                        ↓
              正式订单 → 订单流水

导航栈（原型）：go(id) push；返回 goBack() pop。首页 → 列表 → 补全；或首页卡直接 → 补全。归档成功 toast「已归档」后返回上一页并刷新卡流/列表。

5.3.7 完成归档

校验（原型）

  1. 明细模式且无项目/产品 → toast「请添加项目/产品，或使用快捷开单」，不归档。
  2. 未选任何员工 → toast「未指定服务员工」——仍允许继续归档（弱提示）。

成功

  1. 写入员工、备注、性别名、业绩行等；status → done。
  2. 桥接流水 BillingDemo.recordFromHostCheckout（若可用）：开单人语义「自助买单」，归档人如「店员小陈」。
  3. toast「已归档」→ 关闭补全页 → 刷新首页卡流与列表（该单不再出现在待处理）。

·7. 业务规则（汇总）

  1. 半成品 ≠ 正式订单；归档后才进流水。
  2. 不改动开单结账 / 价目表 / 业绩设置 / 提成设置 / 订单流水既有逻辑。
  3. 实付与支付渠道商户端不可改。
  4. 内容侧：至少「有明细」或「快捷开单」才能归档。
  5. 员工可选；无员工可归档（toast 提示）。
  6. 「散客」按钮（选人）= 非顾客指定；点客 = 顾客指定。
  7. 提成演示比例 10%（真实比例以门店提成设置为准，本功能不改设置模块）。
  8. 首页/列表按下单时间排序；首页最多 5 张；尽头右滑进列表；列表默认可看全部日期 pending。
  9. 选人 sheet 不展示本上下文已占用员工；无可选时 toast、不打开。

·8. 验收要点（P0）

  1. C 端语义：说明自助订单为半成品；归档后进流水。
  2. 首页卡流按下单时间取前 5；尽头右滑二楼进列表；列表左缘可右滑回首页；点卡进补全。
  3. 列表无 Tab；默认日期「全部」；日历快捷为「全部 | 今天」；筛选支付仅三档；筛选图标无灰圆底。
  4. 价目「猜你想加」三源混合最多 6 + 信息标推荐规则（列表无排列规则问号）。
  5. 票卡恰 2 项无角标；≥3 为第二项名后「…」+ 灰圆白字件数；当日只显时刻、非当日只显日期；金额去尾零；首页 108 宽露出第 4 张；无「更多」、尽头右滑进 s16；会橙/散蓝。
  6. 散客名与性别三态正确。
  7. 价目 sheet 无 ×；快捷开单为橙底白字+白闪电右对齐。
  8. 选人：过滤已占用；点客/散客一点即落；白底、安全区、末行无线。
  9. 业绩表头「员工/业绩/提成」；均分可改、提成=×10% 只读；笔标可见。
  10. s17 有状态栏；持卡行时间日期与时刻之间为双空格。
  11. 归档成功 toast，卡流/列表移除该 pending；流水可桥接出现。
  12. 外网字体不阻塞首屏；流水大包可按需加载。
