先读这几条（贯穿全文）

  1. 本期是基于 RTB 线上开单结账 的 优化改版，不改变其他未涉及的功能逻辑。凡本文未单独描述的交互、文案、接口，均沿用线上现有实现。
  2. 页面顶部顾客卡片：默认态为单默认头像 +「散客」（未选择顾客时）；从顾客列表选择「男散客 / 女散客」后仅显示对应的一个性别头像 + 文案「男散客 / 女散客」；点击头像或姓名均进入顾客列表（s4），性别切换仅通过 s4，不再点头像切男女；「选择顾客」进入顾客列表，列表仍保留「男散客 / 女散客」选项，列表内 VIP 标签样式做了微调。默认态产生的订单顾客记为「散客」，头像为默认头像。
  3. 从顾客列表选择 会员 后，开单结账页顶部卡片切换为 会员样式。原会员信息卡默认 折叠 会员所持权益，本期改为 保持展开、展示全部持有权益且不可折叠收起；字段显示规则维持现有规则。会员姓名右侧的 VIP 标签只是原型展示用的临时资源，开发时保持该位置现有 VIP 标签逻辑不变。
  4. 添加项目 / 产品时的 UI UX 是本期最大的修改：参照博卡小店通的 sheet 弹窗样式，按现有逻辑做了适配；弹窗内展示 数量 + 应付（元）（应付带笔形编辑图标），并在弹窗内 内嵌「选择员工」翻转选择 UI（点击卡片翻转成按钮进行点客/散客 → 小工/中工/大工选择）。购物车有项后，点击「下一步」进入 开单结算页（s6）；购物车为空时，s1/s5 底部主按钮显示为「快捷开单」（橙底 #FF8956 + 闪电图标），点击进入快捷开单流程（s2）。当会员持有的权益使项目/产品产生划线价（原价灰色划线 + 红色优惠价）时，弹窗「应付」默认即为该优惠价。
  5. 「快捷开单」功能（原「快捷开单」全局更名）：无需常规流程的繁琐操作，只需输入金额即可完成开单结算，并 可选填 服务员工信息和开单内容。结算第二步为 快捷开单结算页（s7），金额按原价计算，不做身份折扣。快捷开单与小程序「自助买单」的纯金额支付不是同一种功能、互不相关。开单页 Tab 上方的「快捷开单」入口行已移除，入口改由底部空车主按钮承载。
  6. 补充展示页面：门店流水（s8，快捷开单在流水中的展示）、选择退款项目（s9，快捷开单退款）、业绩设置（s10，劳动业绩含「快捷开单」分类）、提成方案（s11，劳动提成含「快捷开单」分类）。入口为原型左侧导航直达，不承载业务链路；对应业务逻辑以线上为准。其中「经营分析 → 门店经营报表」的项目 TOP5 排行不包含「快捷开单」（经营分析属另一产品线，此处仅记录本侧规则）。
  7. 该模块的 其他功能保持现有状态（支付、会员卡业务等均以线上为准）。挂单限制：快捷开单不可挂单；购物车未添加任何物品时不可挂单（按钮置灰，点击 toast 提示原因）。本期已移除会员信息卡上的「办卡」按钮，会员卡仅保留「更换顾客」。开单结账页（s1/s5）原有的搜索栏本期已删除，原型与文案均不再包含；搜索能力如线上另有入口，以线上现有版本为准。
  8. 开单结算 s6 / 快捷开单结算 s7 的交互效果与各类弹窗（员工面板、权益选择 sheet、备注 sheet、小计编辑、toast 等）以当前在线版本为准，原型中的仅为评审演示，原型细节不作为开发验收约束；本 PRD 已明确写出的本期业务规则（会员划线价、快捷开单权益、点客/散客、应付默认优惠价、挂单限制、单号交互、默认散客卡、无产品隐藏 tab 等）仍为开发约束。
  9. 输入与联动口径（原型已同步）：金额格式 整数≤6位、小数≤2位、上限 999999.99；快捷开单 空金额不可「去收款」；开单内容 ≤50 字；应付/小计 可手动编辑（对焦即清空，失焦为空时还原），改价后该明细不可使用权益（改价判定以「应付/小计 ≠ 单价/权益优惠价 × 数量」为准）。
  10. 单号（s6/s7）：左侧标签为「单号」；右侧默认展示灰色文案「结账后自动生成」；点击右侧可进入手动输入自定义单号（同行变为可编辑输入框）。结账时若未手动填写，由系统自动生成单号。
  11. 价目表无产品时：若门店价目表未录入产品（产品为空），开单页（s1/s5）Tab 不显示「产品」，仅显示「项目」，且「项目」在 Tab 区域居中。本规则为产品约束；当前原型演示数据含产品，原型可不切换演示该态。

交互行为与文案以 index.html 当前表现（含本版同步后的口径）为准。

1背景 / 目标 / 范围 / 能力映射

1.1 背景

RTB 线上开单结账经过一段时间运营，线下调研反馈：

  • 常规开单需先选顾客、选项目、配员工、填备注，流程较长，存在「只想快速收一笔钱」的场景；
  • 顾客卡片与顾客列表在性别表达、头像素材上体验欠佳；
  • 会员所持权益信息默认折叠，收银员核对权益时需要额外操作；
  • 添加项目/产品时的信息组织与操作路径不符合当前门店操作习惯；
  • 快捷开单缺少结算第二步、流水展示、退款与业绩/提成配置等闭环展示。

本期在不改变其他功能逻辑的前提下，对开单结账做定点优化，并为快捷开单补齐逻辑补充页面。

8业务规则

  1. 身份切换：默认散客（文案「散客」、单默认头像）；选会员 → 会员；选男/女散客 → 散客性别态（对应单头像）。s2/s3/s6/s7 顶部卡片随身份切换，后续元素随卡片高度下移。
  2. 散客默认态：未选择顾客时为单默认头像 +「散客」；订单记为「散客」。从列表选男/女散客后仅显示对应单头像 + 文案；点击头像/姓名进 s4；性别切换仅通过 s4。
  3. 会员卡权益：保持展开、全部可见、不可折叠；字段显示规则维持现有。
  4. VIP 标签：原型为临时展示资源；开发保持该位置现有 VIP 标签逻辑不变。
  5. 金额格式：整数≤6 位、小数≤2 位、上限 999999.99、禁「.」开头、前导 0 剔除、不可为负。
  6. 快捷开单：空金额不可「去收款」（toast「请先输入金额」）；员工/开单内容选填；金额按原价计算，不做身份折扣；不可挂单；与小程序「自助买单」的纯金额支付不是同一种功能，互不相关。
  7. 挂单限制：购物车未添加任何物品时不可挂单；快捷开单流程（含 s7）不可挂单。按钮置灰，点击 toast 提示原因。
  8. 单号：s6/s7 左侧「单号」，右侧默认「结账后自动生成」；点击可手动输入；未填写则结账后系统生成。
  9. 无产品 Tab：价目表未录入产品时，开单页仅显示「项目」且居中。
  10. 应付/小计编辑：带笔形编辑图标；对焦即清空、失焦为空还原；改价后 s6/s7 该明细权益锁定（toast「改价商品不可用权益」）；改价判定以「单价 / 权益优惠价」× 数量为基准。
  11. 权益自动匹配（s6）：明细未改价且未手动清除时，会员自动匹配其持有的全场最优折扣权益（演示为超值折扣卡 8 折，与价目划线价同源）、散客自动匹配首张优惠券；手动取消后不再自动覆盖。
  12. 数量：步进 1~999。
